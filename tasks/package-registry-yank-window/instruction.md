Fresh installs and the advisory feed disagree about which package versions are blocked at the promoted index snapshot. Some versions stay marked blocked past the end of their yank window. Some packages resolve with a dependency chain that still reaches an active yank. Optional dependency edges are treated like required ones. Revoked yank rows still show up as live. The advisory digest keeps entries for versions that are no longer under an active yank, and it keeps low-severity rows that the operator severity floor of high should drop (critical above high above medium above low).

Bring installability, the active yank set, and advisory consistency into agreement for the promoted snapshot. Do not rewrite fixture rows under `/app/data/crates/`, `/app/data/yanks/`, `/app/data/advisories/`, or `/app/data/index/snapshots/`; the verifier holds its own integrity ledger for those bytes and will fail the run if any input drifts.

Write `/output/yank-reconcile.json` using `/app/bin/indexctl report --out /output/yank-reconcile.json`. The report includes integer `snapshot_gen`, hex string `index_digest`, an `installable` list of `{crate, version}` pairs, a `yanked` list of `{crate, version}` pairs, and hex string `advisory_digest`. `/app/bin/advscan window` prints the same integer as `snapshot_gen`, and `/app/bin/advscan digest` prints the same hex string as `advisory_digest`. The operator table at `/app/config/l7/k9.toml` must end the run with these exact literal tokens: `bound_mode = "half_open"`, `honor_revokes = true`, `adv_live_only = true`, `adv_floor = "high"`; equivalent spellings for `bound_mode` (for example `"halfopen"`, `"exclusive_upper"`, `"open"`) are rejected even when the runtime honors the same semantics. See `/app/ops/runbooks/ops_policy.md` for the full policy.
