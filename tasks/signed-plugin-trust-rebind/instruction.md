Signed-plugin trust under `/app` is split after a key rotation. `/app/bin/jarcheck` and `/app/data/fixtures/surface_attestation.json` look healthy. That path is not admission authority. Forged, replayed, and revoked plugin credentials still count on the surface path. Sibling epochs disagree on usable signing material. Dynamic fixtures under `/app/data/fixtures/` show an authentic-versus-injected split the surface path ignores.

A pre-incident capture under `/app/data/fixtures/` records five working verifier samples (seed hex, payload, check byte) across epochs and lanes. Material is not exported there. Signing material is derived per frame from the authoritative manifest seed: each material byte mixes that seed byte with the epoch low byte (rotated by an index-dependent amount), a small index-dependent stride, the frame lane id, and the weave strand from `/app/ops/trust_policy.toml` — not a plain seed copy. The integrity check is a keyed fold of each payload byte against that material (wrapping sum of payload XOR material). Surface plain-sum checks are not deep authority. Credentials signed only under a prior material schedule must quarantine as integrity failures. `/app/bin/framecheck --frame <path>` validates a single credential frame under those deep rules (exit 0 / ok when integrity matches); use it to probe candidates. It is not a full admission publish path.

Publish `/output/plugin-ledger.json` via `/app/ops/run-admit.sh` as the verified trust view. Accepted counts credentials that fully contribute to trust from both signed WAL segments under `/app/data/signed_segments/` and credential JSONL feeds under `/app/data/credentials/`. Credentials whose timestamp is above the authoritative epoch watermark do not contribute to accepted or mutual-presence. Suspended credentials keep mutual-presence for fleets that require every listed lane without raising accepted. Revoked credentials satisfy neither, so an epoch is omitted when a required lane is only revoked. Replay tracking is global per epoch-and-lane across all WAL segments in capture order: timestamps must strictly advance on that combined stream; a non-advancing credential is a replay and belongs in quarantine even when integrity is otherwise valid. Backend status is active or inactive. Also publish `/output/quarantine.json`. Quarantine lists one row per rejected credential (no epoch/lane deduplication — distinct timestamps on the same epoch and lane are separate rows). Revoked quarantine rows are WAL-only.

Normative plugin-ledger.json fields (version 1): top-level integer version; backends array of objects with string name and string status (active or inactive); epochs array of objects with integer id, string profile, and integer accepted.

Normative quarantine.json fields (version 1): top-level integer version; rejected array of objects with integer epoch, string lane, integer ts, and string reason (integrity_failure, replay, or revoked).

Surface OK is not deep authority. Deep admission must disagree with the surface fixture on accepted tallies, stay stable across identical re-runs, and match a rebuild from `/app` sources. Hand-written stand-ins fail. Leave `/app/data/fixtures/` untouched.
