The particle fluid runner at `/app` picks up four bundled checkpoints — a shock tube, a blast wave, a shear layer, and a self-gravitating polytropic star — and resumes them under the kernel declared in `/app/data/policy/handoff.spec`. Each checkpoint spec under `/app/data/checkpoints/` was written by a different kernel than the one the policy now names. The current runner produces a report that clears the schema but the per-scenario residuals blow past every band listed in `/app/docs/reconcile-schema.md`: moment_zero_residual, h_consistency_residual, momentum_residual, angular_residual, gravity_virial_residual, and chunk_stability_delta all fall outside their bands.

Drive `/app/scripts/run_reconcile.sh` so the report at `/output/reconcile-report.json` sits inside every per-scenario band the schema doc lists. The top level is an object with schema_tag, a scenarios array (one row per resumed checkpoint), and an invariants object. Each scenario row names the scenario and carries kernel_source, kernel_target, particles, converged (JSON boolean true/false), and the residual fields above. The invariants object echoes recomputed maxima across rows as max_moment_zero, max_momentum, max_angular, and max_h_consistency. Every scenario row must be marked converged in the final report.

Bit-identity of per-particle intermediates is not required; scenario-band agreement on every residual, chunk-invariant summation for any positive chunk size the runner or the verifier chooses, and honoring the policy authority when the checkpoint kernel disagrees with the policy kernel are. Rebuild the runner for each source edit — `/app/scripts/run_reconcile.sh` rebuilds `/app/ws` and regenerates the report in one step. The verifier discards prior report files and rebuilds `/app/ws` from source prior to scoring, and it also exercises the current internal crates directly with its own probe inputs. Consult `/app/docs/reconcile-schema.md` for the per-scenario bands and the authority rule.
